# Release Planning

## Purpose
Plans release scope, timeline, and dependencies for the upcoming release.

## Role
Release Manager

## Phase
Planning + Release

## Triggered By
Sprint planning approval; ongoing through the release cycle.

## Inputs
- PM's `release-scope-management` classification (Must Ship / Should Ship / Can Hold)
- Sprint completion status from PM

## Process
1. Read PM's `release-scope-management` to determine story classification.
2. Identify which stories are in this release.
3. Coordinate with PM on sprint completion status.
4. Track release timeline against sprint progress.

## Outputs
Release scope and timeline tracked for the sprint's release.

## Quality Gates
- [ ] Release scope matches PM's Must Ship / Should Ship / Can Hold classification
- [ ] Timeline coordinated with PM's sprint status
- [ ] Scope changes communicated to PM promptly
