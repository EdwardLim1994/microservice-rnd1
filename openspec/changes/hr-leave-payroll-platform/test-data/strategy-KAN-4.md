# Test Data Strategy — KAN-4 (Leave Request, Approval & Balance Tracking)

| Data state | Store | Source |
|---|---|---|
| Employee with full annual/sick balance | PostgreSQL (`leave-infra`) | fixture: `leave-balance-fresh.sql` |
| Employee with near-exhausted annual balance (boundary test for unpaid conversion) | PostgreSQL | fixture: `leave-balance-near-limit.sql` |
| Pending leave request awaiting supervisor | PostgreSQL | fixture: `leave-request-pending.sql` |
| Pending leave request from a Supervisor awaiting HR Admin | PostgreSQL | fixture: `leave-request-pending-supervisor.sql` |
| Approved/rejected historical requests (for history table) | PostgreSQL | fixture: `leave-request-history.sql` |
| `leave.requested` / `leave.reviewed` Kafka events | Kafka (via Debezium CDC) | generated by fixture inserts/updates through the real CDC pipeline in integration tests, not hand-crafted messages |
| Employee/supervisor hierarchy | PostgreSQL (`employee-infra`, cross-service) | reuses KAN-2 fixtures via gRPC test double or shared test compose |
